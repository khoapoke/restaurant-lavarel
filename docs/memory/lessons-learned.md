# 🎓 BÀI HỌC KINH NGHIỆM & SỬA LỖI (LESSONS LEARNED)

Hệ thống lưu trữ các lỗi gặp phải trong quá trình phát triển dự án `restaurant-lavarel`.
Định dạng: `[Lỗi gặp phải] -> [Nguyên nhân] -> [Giải pháp fix]`

---

- **[Tin chat đến sau lượt đọc trong cùng một giây bị coi là đã đọc]** -> **[Timestamp mặc định chỉ chính xác đến giây; so created_at > seen_at bỏ sót tin mới]** -> **[Lưu con trỏ ID lớn nhất thực sự có trong snapshot trả về, cập nhật đơn điệu; test đóng băng thời gian để hai sự kiện cùng giây vẫn tăng badge/thông báo]**

- **[SMTP báo Unsupported mail transport [] dù transport cấu hình smtp]** -> **[MAIL_URL để chuỗi trống vẫn đi qua bộ phân tích URL và ghi đè transport về null]** -> **[Để MAIL_URL=null hoặc bỏ biến URL khi dùng host/port; kiểm tra khởi tạo transport trước khi thử gửi, không in cấu hình chứa mật khẩu]**
- **[Tra cứu đơn nội bộ nhưng lượt tư vấn AI tiếp theo vẫn có thể gửi kết quả đó ra ngoài]** -> **[Lịch sử chung chứa cả tin tra cứu và câu trả lời cục bộ]** -> **[Đánh dấu DONE_LOCAL/LOCAL và loại cả hai phía khỏi context gửi Gemini; test hồi quy kiểm nội dung outbound request]**
- **[Worker và HTTP có thể chạy phiên bản code khác nhau khi phát triển]** -> **[Queue worker là tiến trình lâu dài, không tự nạp lại class đã dùng]** -> **[Khởi động lại worker sau khi sửa code/config; dùng DB sao chép và worker riêng cho browser E2E]**

- **[Lệnh php và composer không nhận diện trong PowerShell (CommandNotFoundException)]** -> **[Laragon chưa được đưa vào biến môi trường PATH hệ thống của User]** -> **[Thêm đường dẫn `C:\laragon\bin\php\php-8.3.33-Win32-vs16-x64` và `C:\laragon\bin\composer` vào PATH khi thực thi lệnh CLI].**
- **[Composer không tải được package zip (The zip extension and unzip/7z commands are both missing)]** -> **[Dòng `;extension=zip` trong `php.ini` của Laragon đang bị comment]** -> **[Mở comment `extension=zip` trong `C:\laragon\bin\php\php-8.3.33-Win32-vs16-x64\php.ini`].**
- **[Gọi API yêu cầu auth mà không truyền token bị lỗi 500 RouteNotFoundException và lộ stack trace]** -> **[Khi thiếu header Accept: application/json, Laravel mặc định redirect về route('login'). Do project thuần API không có route này nên ném lỗi 500 kèm debug trace]** -> **[Cấu hình `$middleware->redirectGuestsTo(fn () => null);`, tạo middleware `ForceJsonResponse` ép header `Accept: application/json` cho mọi route `api/*`, và bắt `AuthenticationException`, `RouteNotFoundException`, `Throwable` trong `withExceptions` trả về JSON 401/500 chuẩn không lộ field nhạy cảm].**
- **[Đơn POS/online không bao giờ chuyển `READY` dù mọi món đã xong]** -> **[`Eloquent\Builder::pluck()` áp dụng cast nên trả về enum `KitchenItemStatus`, so sánh `in_array(..., ['READY'], true)` với chuỗi luôn sai]** -> **[So sánh trực tiếp với case enum (`KitchenItemStatus::READY`) hoặc dùng query builder thuần khi cần chuỗi].**
- **[Quy tắc đặt bàn trước 30 phút/2 giờ và "hôm nay" tính sai 7 tiếng]** -> **[`app.timezone = UTC` trong khi khách nhập giờ Việt Nam dạng naive datetime]** -> **[Đặt `APP_TIMEZONE=Asia/Ho_Chi_Minh` làm mặc định trong `config/app.php`].**
- **[Test đổi tài khoản giữa các request trả 403 sai]** -> **[Guard Sanctum được cache trong cùng instance ứng dụng của test nên user đầu tiên bị tái sử dụng]** -> **[Mỗi test dùng một vai trò qua HTTP; chuẩn bị trạng thái của vai trò khác bằng model/factory].**

- **[Test feature gửi request thiếu header vẫn pass/không đúng kỳ vọng (ví dụ thiếu `Idempotency-Key` nhưng nhận 201)]** -> **[`withHeaders()` trong test Laravel được giữ lại cho mọi request tiếp theo của cùng test]** -> **[Gọi `$this->flushHeaders()` trước request cần kiểm tra thiếu header].**
- **[`assertJsonPath('...', 45000.0)` thất bại dù giá đúng]** -> **[JSON encode số thực tròn `45000.0` thành `45000`, decode ra `int`]** -> **[So sánh bằng closure `fn ($v) => (float) $v === (float) $expected`].**
- **[Regex trong file PHP/JS sinh bằng heredoc qua công cụ shell bị chèn ký tự backspace (`\b` → 0x08) hoặc mất dấu `\`]** -> **[Công cụ shell xử lý escape trong heredoc]** -> **[Viết file có `\` bằng công cụ ghi file trực tiếp, kiểm tra bằng `grep -c $'\x08'`].**

- **[Endpoint công khai “tham gia bàn” cấp quyền cho người giữ QR cũ]** -> **[Chỉ ràng buộc visit token theo phiên, còn `/join` vẫn tin QR in cố định]** -> **[QR chỉ để nhận diện; quyền vào phiên cần bí mật theo phiên (mã bàn) hoặc nhân viên duyệt; viết test cho cả trường hợp bỏ header].**
- **[Idempotency-Key giữ trong `useRef` vẫn gửi trùng sau reload]** -> **[Key mất khi trang tải lại trong khi giỏ được khôi phục]** -> **[Ghi key + payload vào storage bền vững trước khi gửi, chỉ xóa khi biết chắc kết quả; kiểm thử bằng Playwright `route.fetch()` rồi `route.abort()`].**

- **[Test đổi vai trò vẫn trả 401 sau `travelTo` xa]** -> **[Token đăng nhập hết hạn sau 8 giờ (AuthService); `travelTo(22:15)` từ 12:00 làm token cũ hết hạn]** -> **[Đăng nhập lại sau khi du hành thời gian xa; helper `as($username)` gọi `app('auth')->forgetGuards()` trước mỗi request đổi người].**
- **[Test giả lập "đơn QR chưa thanh toán" bằng cách sửa cờ `THANH_TOAN.trang_thai` nhưng hệ thống vẫn cho giao]** -> **[Sau ADR-023, sổ giao dịch là nguồn sự thật; cờ tổng hợp được tính lại từ phân bổ]** -> **[Tạo đơn mới chưa có khoản tiền nào thay vì sửa cờ tổng hợp].**
- **[Món đã nấu bị hủy theo yêu cầu khách (vẫn tính tiền) làm phiên bị coi là rỗng, và còn hủy được phiên để né tiền]** -> **[Các kiểm tra "món còn hiệu lực" lọc theo trạng thái CANCELLED thay vì theo số phần tính tiền]** -> **[Món thuộc hóa đơn khi `so_luong_tinh_tien > 0` bất kể trạng thái bếp; E2E trình duyệt phát hiện, đã có test hồi quy].**
- **[Lọc bí mật trong nhật ký chỉ ở tầng đầu, khóa nằm trong mảng lồng (payload) vẫn được lưu]** -> **[`Arr::except` không đệ quy]** -> **[Lọc đệ quy; test kiểm token/mật khẩu/mã bàn lồng nhau không xuất hiện].**
- **[Kiểm tra "lượt của chính khách chồng giờ" chặn hai lượt cách nhau vài phút]** -> **[Dùng chung hàm overlap có cộng 15 phút dọn bàn — ràng buộc của bàn, không phải của khách]** -> **[So khoảng dùng bàn thuần cho trùng lịch của cùng khách].**
- **[E2E chạy lặp trên DB dev thất bại vì dữ liệu lần trước (mã giao dịch trùng, yêu cầu duyệt cùng nội dung)]** -> **[Sổ tiền bắt mã tham chiếu duy nhất; locator theo văn bản trùng]** -> **[Sinh mã/nhãn theo lượt chạy, gắn định danh `[E2E-NGOAI-LE]` và dọn đúng dữ liệu có định danh trước khi chạy].**

- **[Cùng một khoản chuyển khoản ghi hai lần khi admin xác nhận tay rồi ngân hàng gọi webhook]** -> **[Khóa duy nhất ghép nhãn nguồn (`VIETQR`, `MBBank`…) — mỗi đường ghi một nhãn khác]** -> **[Định danh theo thứ khách thật sự chuyển vào: ngân hàng + tài khoản nhận + mã; nhãn nguồn chỉ là metadata; migration tính lại khóa cũ và gắn cờ, không gộp tiền]**
- **[Webhook ký hợp lệ với nội dung `DH999999` trả 500]** -> **[Mã đơn đọc từ nội dung chuyển khoản được ghi thẳng vào cột khóa ngoại]** -> **[Dữ liệu từ bên ngoài chỉ thành khóa ngoại sau khi kiểm tra tồn tại; không thì lưu để xem xét]**
- **[Hoàn một phần sau thanh toán làm phiên POS kẹt (không thu thêm, không mở lại, không đóng)]** -> **[Hoàn tiền giảm "đã thu" nên thanh toán tụt về PARTIALLY_PAID trong khi hóa đơn PAID]** -> **[Tách "hoàn phần nhà hàng nợ khách" và "bồi hoàn" (giảm khoản phải thu); bắt người dùng chọn rõ khi vượt phần đang nợ]**
- **[Test cũ xanh nhưng mã hóa đúng hành vi lỗi (409 khi ghi khoản thứ hai, đơn hẹn xuống bếp ngay)]** -> **[Test viết theo hành vi đang có thay vì theo chính sách]** -> **[Khi sửa theo review, đọc lại test cũ đối chiếu chính sách; viết lại test và nêu rõ trong báo cáo, không coi "suite xanh" là bằng chứng]**
- **[Bộ đo tương phản tự viết báo 0 vi phạm cả khi chèn lại CSS lỗi]** -> **[Luật chèn không nằm trong `@layer` nên thua `!important` trong layer]** -> **[Kiểm chứng bộ đo bằng cách tái tạo lỗi đúng tầng cascade (đã báo 1,25 : 1) trước khi tin kết quả "0 vi phạm"]**
- **[Kịch bản `ui-smoke` treo sau lỗi strict mode khi DB có nhiều phiên mở]** -> **[Lỗi xảy ra trước `browser.close()` nên tiến trình không thoát]** -> **[Đóng trình duyệt trong `finally`; chọn phần tử đầu khi dữ liệu có thể có nhiều]**

- **[Sửa định danh chuyển khoản lần 1 vẫn gộp nhầm hai ngân hàng]** -> **[Dùng số tài khoản đơn độc để suy ra ngân hàng; test chỉ phủ "cùng mã, khác tài khoản" mà không phủ "cùng dãy số, khác ngân hàng"]** -> **[Thông tin do nguồn nêu rõ luôn thắng suy đoán; test ma trận cả trường hợp phải gộp và không được gộp]**
- **[Hoàn một khoản áp cho hai đơn: tổng đúng nhưng từng đơn sai]** -> **[Một dòng tổng gắn một đơn trong khi dòng chi tiết (đảo phân bổ) trải nhiều đơn; số liệu đơn lại cộng theo dòng tổng]** -> **[Ghi dòng chi tiết ở cùng độ chi tiết với nơi đọc số liệu; gom yêu cầu bằng khóa chung thay vì một dòng tổng]**
- **[Test nghiệm thu xanh ngay lần đầu]** -> **[Chưa chứng minh test bắt được lỗi]** -> **[Dựng lại logic cũ tạm thời (sao lưu + so sha256 khi khôi phục), chạy test để thấy FAIL, rồi khôi phục]**
- **[Migration tách hoàn nhiều đơn nhưng gán tiền dư sang nhầm đơn]** -> **[Giữ mã đơn trên dòng hoàn tổng cũ cho phần chưa phân bổ; bỏ qua dòng chỉ có một đơn đảo phân bổ]** -> **[Tách phần dư về đơn đích của giao dịch (không có đích thì để null), tính lại cả đơn đích và đơn cũ; test đủ một/nhiều đơn, đích ngoài phân bổ và chạy lại không đổi tổng]**

- **[Code mới làm hỏng môi trường dev đang chạy: scheduler lỗi "no such column: dispatched_at" mỗi phút]** -> **[Sửa code trong cây làm việc là "triển khai" ngay cho `artisan serve`/`schedule:work`, trong khi migration mới chưa được phép chạy trên dev]** -> **[Khi thêm cột mà không tự migrate được, viết code chịu được schema cũ (kiểm tra cột một lần/request, bỏ ghi cột mới, tạm dừng tác vụ nền kèm cảnh báo) và test bằng `down()` của chính migration; đọc log dev bằng cách đếm mẫu lỗi, không in nội dung]**
- **[Bộ đo tương phản báo tiêu đề Modal chỉ 1,34 : 1 dù chữ đậm trên nền sáng]** -> **[Tailwind 4 trả màu `oklab(...)`; bộ đo lấy số thô trong chuỗi làm RGB]** -> **[Quy đổi màu qua canvas `fillStyle` → `getImageData`; tự kiểm bộ đo bằng một cặp màu đạt và không đạt trên nền oklab trước khi tin kết quả]**
- **[Đảo tạm code để chứng minh test bắt lỗi nhưng test vẫn xanh]** -> **[opcache CLI (`revalidate_freq=2`) dùng bản biên dịch cũ khi chạy ngay sau khi ghi file]** -> **[Chờ ≥ 3 giây sau khi ghi trước khi chạy test, khôi phục và so sha256; khi một lớp bảo vệ bị đảo mà test vẫn xanh, kiểm tra lớp khác có che không rồi đảo đúng lớp]**
- **[Python sửa file trên Windows biến LF thành CRLF, `grep -c $'\r'` của Git Bash vẫn báo 0]** -> **[`open(..., 'w')` ở text mode dịch `\n`; grep MSYS bỏ qua CR]** -> **[Đọc/ghi nhị phân (`rb`/`wb`), kiểm tra bằng `b'\r\n' in data`]**
- **[Mockery `andThrow(a, b)` ném cùng một exception hai lần]** -> **[Tham số thứ hai là message, không phải exception kế tiếp]** -> **[Dùng `andThrowExceptions([a, b])`]**
- **[Đổi tài khoản ở tab khác nhưng vẫn hiện biên nhận của khách trước]** -> **[AuthContext đổi user nhưng trang thông báo giữ state và polling chỉ khóa theo số trang]** -> **[Remount toàn bộ trang thông báo theo accountId để xóa danh sách, modal, form, phân trang và hủy request cũ; kiểm cả phản hồi đến muộn]**
- **[Retry cùng tin chat tạo nhiều job sau khi khóa unique hết hạn]** -> **[HTTP dispatch trực tiếp, bỏ qua lease và kiểm tra hàng đợi của scheduler]** -> **[HTTP/scheduler dùng chung claim nguyên tử ai_dispatched_at và kiểm queue bị tồn; chỉ đánh dấu sau khi claim, vẫn phục hồi job mất sau lease]**
- **[Lời mời đánh giá cũ bị gửi lại sau nâng cấp]** -> **[Khóa sự kiện mới không nhận ra notice cũ thiếu limit_key]** -> **[Trong khóa tài khoản, tính giới hạn ngày trên cả lịch sử và quy entity cũ về cùng bữa/POS; giữ nguyên notice_id và đánh giá đã lưu]**
